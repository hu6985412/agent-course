## 二、对话实录

> 以下按主题还原。为可读性做了压缩，但**所有输出、错误和判断都是原始的**。
> 我的失误也没有修饰——它们在这份文件里的价值跟正确答案一样高。

### 主题 1 · 阶段1 六小节引导（对方每节都抓到了核心）

- **第1节 纯向量翻车**：我列了四类失效（专有名词/标识符/罕见术语/否定对比），给 2026 生产数字（dense-only Recall@10 0.58–0.65，混合 0.72–0.85）。对方抓到"①专有名词最致命——财报专业术语相近、向量差别不大但实际差很多"。
- **第2节 BM25 公式**：讲 IDF/k1/b，MySQL `MATCH...AGAINST` 同源。对方答"b 更值得调（财报块长短不一）"，并正确判断"扣非/归母向量近是因为共享'净利润'上下文被平均，BM25 当不同 token 分开"。
- **第3节 多路召回**：讲两路并行各 top20 → 按 chunk id 合并去重。问建什么语料，对方选 **B（财报/可转债风格小语料）**——让第①类失效自然暴露，结论还能喂 W09。
- **第4节 RRF 融合**：手算 X（单路#1，1/61）vs Y（双路#15，2/75）——Y 靠前，共识 > 单路极值。对方答对"想保精确命中调小 k"。
- **第5节 Query 改写**：讲三类原句翻车（指代/问句/多意图）。对方判"问句式稀释意图最危害"，选 **A（轻量版：解指代+关键词提取，不塞 HyDE）**。
- **第6节 Cross-encoder**：讲 bi/cross-encoder 区别。对方答对"方案③ cross-encoder 能分'避免vs检测'反义"，并补"W09 零误匹配还需字段级归一化兜底"。

### 主题 2 · 建语料 + 建库踩坑（两个真实坑）

- **语料设计缺陷**：最初 6 篇每篇 <400 字，切分后每篇 1 chunk，"扣非/归母"同块 → 判别力探针误报"混淆"。扩建到 9 chunks 才分离（踩坑1）。
- **判别力探针子串误判**：初版用"子串 in 块"判断，扣非块解释里写了"=归母净利润−…"导致误判。改直接比目标块/干扰块排名（踩坑2）。
- **gp17 建库**：对方跑 `docker exec -i gp17 psql -U postgres` 报 `role "postgres" does not exist`（容器管理员即 amber）；改 `psql -U amber` 又报 `database "amber" does not exist`（默认连同名库）。最终用 `template1` 跳板建 `w06rag`（踩坑3）。
- **bat PYTHON_HOME 空**：`import jieba` 失败（走系统 3.8.6）；本机 pip 连 pypi.org SSL EOF 装不上。沙箱代装 jieba+openai+psycopg2+sentence-transformers 进 managed venv，bat 指向 venv Scripts（踩坑4）。

### 主题 3 · 三方案对比 + 两个诚实修正（本周最值钱的部分）

- **第一处被打脸（我预测错）**：阶段1 我两次拍胸脯"探针#3 下修/转股价，Hybrid 预期翻盘"。实测 [BM25] ❌、[Hybrid] ❌（目标#3 干扰#1）——两块都讲"转股价"，Dense 也分不清。我诚实修正："混合检索补词法盲区，补不了语义盲区，第④层字段级归一化才是唯一解"。
- **第二处被打脸（我预测错）**：我预测"真 cross-encoder 把 MRR 拉回 1.000"。实测 [Rerank] MRR=0.983 = lexical fallback，**低于** Hybrid(RRF) 的 1.000。根因：9 块小语料上 rerank 的"洗牌"噪声 > 信号增益。
- **真 cross-encoder 成本认知**：本机 CPU 跑 `bge-reranker-v2-m3` 实测 **22996.9ms/query（≈23秒）**，比我第6节引的 GPU 基线 +100ms 慢 ~230 倍。探针#3 真重排只把目标从 #3 提到 #2（部分缓解），仍 ❌。

**教训**：生产 RAG 文章的漂亮数字（Recall 0.72–0.85、rerank +100ms）是"大语料 + GPU"场景；小语料 + CPU 实测会颠覆部分结论，正文必须如实区分，不拿基线当自己语料的真值。

### 主题 4 · 执行规范固化（跨课程）

对方明确：阶段2 实操**全部基于 PowerShell**，前置调用 `start-env-windows.bat` 加载 API 参数，其他配置（PG_ 连接）手写 `$env:XXX=`，依赖手写 `pip install`，**不再给 .sh 命令**。已写入长期记忆「实操执行规范」段，W07–W15 复用。

## 四、方法论总结（这一周沉淀下来的）

1. **预期要可证伪，别拍胸脯**：我两次预测"探针#3 Hybrid 翻盘""真重排 MRR 拉回 1.000"，实测都打脸。正确姿势是"预期 X，跑出来验证"，而不是"断言 X 必然发生"——被真实数据打脸的结论比漂亮预测值钱。
2. **小语料会伪造指标**：9 chunks / 30 题，top10 必含全部块 → Recall 全 1.000 是天花板，区分不出方案。真实区分力在 MRR 与判别力探针。评测集规模不够时，别把 Recall 当真值。
3. **生产数字有隐藏前提**：RAG 文章的"rerank +100ms / Recall 0.72–0.85"是"大语料 + GPU"。本机 CPU + 9 块小语料实测：rerank 23s/query、MRR 反降。引用任何基准数字必须标注其硬件/语料前提。
4. **检索层救不了语义相似块**：BM25（词法）/ Dense（语义）/ 真 cross-encoder（逐字 attention）三道防线下修/转股价这对都分不出优先级，只有字段级归一化兜底。这是 W09 毕业项目"零误匹配"验收的提前剧透。
5. **踩坑必须有终端输出作证**：探针子串误判、gp17 建库 role 不存在、bat PYTHON_HOME 空导致 import jieba 失败——每个坑都是真实报错驱动的定位，不是脑补。
6. **执行规范跨课程固化**：PS + bat 加载 + 其他配置手写 + 不提供 .sh；依赖统一走 managed venv（本机 pypi SSL 中断时沙箱代装）。W07–W15 复用，不再踩这些环境坑。
