# Agent 开发实战 15 周

> 面向后端工程师的 Agent 开发通关记录。每周一个可运行的项目，从手搓循环到生产上线。

## 这个系列是什么

不是又一份「AI 速成清单」。这是一份**面向 PHP / 后端工程师**的 Agent 开发实录：用周次制节奏，把 Agent 从"能调 API"一步步做到"能上线"，每周一个可运行的项目。

每周交付：

- **一篇长文** —— 讲清楚这周的核心概念、为什么这么设计、我踩了什么坑（同步发知乎）
- **一份可运行代码** —— clone 下来配好 key 就能跑，不是伪代码
- **一张验收清单** —— 这周跑通了什么、没跑通什么，如实记录

## 适合谁

| 你是 | 收获 |
|---|---|
| **PHP / Java / Go 后端想转 AI 工程** | 最大的痛点是"要从零学 Python"——这个系列给的是**单一编排栈路径**：Agent 编排只用 Python 攻克一次不打第二遍，PHP/Laravel 负责它本来就擅长的接入层与工程治理 |
| 前端 / 全栈想做 AI 应用 | 第 9、15 周有完整的 Agent 前端交互设计（流式、过程可视化、图表卡片） |
| 已经会调 LLM API，做不出靠谱 Agent | 第 3-4 周手搓循环、第 12 周建评测，这两周是分水岭 |
| 在做 RAG，效果总是不达标 | 第 5-7 周讲透检索链路，第 9 周正面解决"语义相似导致误匹配" |

**不适合**：想找"三天精通 Agent"的人。这个系列的假设是每周投入 10 小时。

## 为什么这条路对后端工程师更省事

Agent 的教学几乎都是 Python 的。后端转过来的最大诱惑是「用 PHP 再实现一遍」——2026 年初 Laravel 官方的 `laravel/ai` SDK 确实已经能做到 Agent 类、工具调用、对话持久化、队列异步、SSE 流式。

**但那是重复劳动。** 循环、状态、持久化、人机协同这些核心难点，你只需要攻克一次。攻克之后，用什么语言把它接进你的业务系统，是另一个（更简单的）问题。

| | 用什么 | 为什么 |
|---|---|---|
| Agent 编排 | Python + LangGraph | 一次攻克，不留第二套实现 |
| 接入与治理 | Laravel（PHP，仅调用端） | HTTP/SSE 消费服务 + 队列异步 + 后台页面与权限 |

**你不需要先成为 Python 专家。** 你需要的是把已有的工程能力（事务、幂等、权限、队列、测试）迁移到 Agent 这个新领域上——而这恰恰是很多 AI 教程不讲、但决定项目生死的部分。这个系列的 W12-W15 全部讲这个。

## 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 编排思想 | LangGraph（Python） | 2026 年生产事实标准，学它其他框架都是子集 |
| 业务接入 | Laravel（PHP，仅调用端） | HTTP/SSE 消费 Python 服务 + 队列异步 + 后台页面；**不写 Agent 逻辑** |
| 工具协议 | MCP（FastMCP） | 跨平台标准，一次写好处处可用 |
| 向量检索 | pgvector | 会 SQL 就上手，混合检索直接写 SQL |
| 评测观测 | Langfuse + 自建测试集 | 开源可自托管 |

选型的完整对比和踩坑记录见 [第 1 周](week-01/README.md) 附录。

## 毕业项目（第 9 周起）：财报与可转债分析 Agent

前 8 周只做一件事：**把能力练出来，不跟具体项目绑定。** 到第 9 周，基本功（工具调用、循环防护、检索链路、框架编排）都跑通了，题目正式定为 **财报与可转债分析 Agent**（A 股年报场景）。

| 标准 | 这个题目怎么满足 |
|---|---|
| 数据公开可复现 | 上市公司定期报告全网公开，读者能自己跑起来，代码可以开源 |
| 有真实工程复杂度 | 「扣非净利润」与「归母净利润」语义高度相似，**检索层面无法区分**——这不是编出来的陷阱，是 W06 实测撞到的 |
| 能覆盖前面的知识点 | 文档解析（W07）→ 混合检索（W06）→ 工具调用与防护（W03/W04）→ 编排状态机（W08）→ 评测（W12） |
| 合规上能公开讲 | 只涉及公开披露信息，不涉及公司内部数据 |

**核心难点不是"取不到数据"，而是"取到了相似但错误的数据"。** W06 的结论已经写明：向量 + BM25 + 重排三道防线都救不了语义相似块。所以毕业项目的主线是**指标语义层**——字段字典 + L1-L2 归一化，验收硬指标是**扣非 / 归母零误匹配**。

> 第 9 周起，每周的文章会给出对应环节的表结构与实现，不在开篇一次性放出。
> 在那之前，各周内容独立成篇，单独 clone 任意一周的代码都能跑。

## 使用方式

```bash
git clone https://github.com/<你的账号>/agent-dev-15weeks.git
cd agent-dev-15weeks

uv venv .venv && .venv\Scripts\activate     # Windows
uv pip install openai python-dotenv rich

cp .env.example .env                        # 填入 API Key
cd week-01 && cat README.md                 # 读正文
cd code && python main.py                   # 跑代码
```

**Windows 用户**：不想每次手打环境变量，就用 [`tools/start-env-windows.bat`](tools/README.md)，
双击即开一个配好 Key 与多模型变量（`CHAT_MODEL` / `EMBEDDING_MODEL` / `RERANK_MODEL`）的终端（**仅 Windows**，需先复制到仓库外再填 Key）。

整个仓库共用一个虚拟环境，不必每周重建。前 8 周的代码互相独立，第 9 周起会复用前面的模块。

## 前置要求

- 任一后端语言的工程经验（正文示例用 PHP / Laravel / SQL 类比讲解，**Agent 代码本身是 Python**）
- 会 SQL
- Python 能读懂基础语法即可，边做边补
- 一个大模型 API Key（DeepSeek 起步即可）
