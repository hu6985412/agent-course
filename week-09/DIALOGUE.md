## 一、对话实录（关键转折点）

### 1. 阶段1 引导：四小节 + 理解检查

按课程四阶段节奏，先讲透架构边界再动手：

- **双运行时**：Python（FastAPI + LangGraph）是唯一智能源；Laravel 只做接入层四件事（HTTP 消费 / SSE 转发 / 队列长任务 / 最简查询页）。
- **指标语义层**：四级匹配（L1 精确 / L2 规则 / L3 模糊 / L4 向量）+ L0 unknown 队列，配否定词保护、易混淆组、近似指标守卫、数量级校验。
- **SSE 流式转发**：FastAPI `app.stream` → Laravel `Response::stream` 原样透传。
- **NL2SQL 安全边界**：只读账号 / 表列白名单 / 参数化 + 结构化意图 / AST 解析拦截。

每节配理解检查。amber 有一处典型误判，被当场纠正：

> **amber 误判**：「raw_name 含扣非关键字 → 用否定词保护机制，或者向量结合 BM25 重排。」
> **纠正**：向量 + BM25 + 重排是**检索层**技巧，对「扣非 vs 归母」这种语义相邻块无效（W06 已预言）。正确解法是**禁术**——含修饰词时直接禁止 L3/L4 模糊，只在精确/规则层匹配。这不是"检索更好"，是"根本不走模糊"。

### 2. 阶段2 实操：amber 两次关键纠偏

这是本周最有价值的部分——不是我教对了，是 amber 用真实业务直觉把设计掰正了。

**纠偏 1：unknown 不是兜底垃圾桶**

> amber：「财报是很严谨的东西，数据要求精准。未命中就不混进已经精准识别的数据内，应该单独处理。净利润是一个单独的关键字段，不应该因为用这个举例子，而强行去把他划分到 unknown 里面去。」

这纠正了一个为了"演示机制"而犯的错：原本把"净利润"强行划进 unknown 来展示 L0 队列。amber 指出——**精准可识别的字段，绝不许因为演示方便被塞进 unknown**。unknown 只收容 legit 无法归类的字段，字典补全优先。设计哲学从此改为"unknown 仅收容 legit 场景"。

**纠偏 2：稀释每股收益被 L3 误配（暴露真 bug）**

> amber（跑 `pipeline_demo.py` 输出）：「稀释每股收益」被匹配成了 BASIC_EPS。

这不是演示问题，是**真 bug**：L3 子串包含过宽，把"稀释每股收益"吸进了"基本每股收益"。修复：新增 `DILUTED_EPS` 字段 + 收紧 `BASIC_EPS` 的 alias（删"每股收益"改"每股收益(基本)"）+ 加**近似指标守卫**（L3 不能把近似指标互相吸收）。这正是指标语义层"护城河"的设计意图被真实数据验证。

### 3. 阶段3 反馈：Laravel 三坑全踩

amber 本机跑通 Python 端（curl 验证 6 帧 SSE + `zero_mismatch: true`）后，Laravel 接入层连踩三坑，每个都有 `laravel.log` 终端输出作证：

1. **协变 500**：`response()->stream()` 返回 Symfony 基类，方法声明 Illuminate 子类返回类型 → TypeError。
2. **空 body（没 500 也没响应）**：`foreach($stream)` —— Guzzle PSR-7 Stream 不可遍历，循环体零执行。
3. **只出第一帧**：清完 OB 后无脑 `ob_flush()` → "No buffer to flush" 警告 → 流中断。

加一个 Python 侧：`build_input() got unexpected keyword 'auto_approve'` —— Edit 未落盘，grep 核验后补上。

### 4. 阶段4 收尾

amber 浏览器最终收到完整 6 帧（classify → extract_node → human_review → normalize_persist → verify → done），`verify` 帧 `zero_mismatch: true`，6 科目全 L1 命中。硬指标达成。

## 三、方法论总结（哪些有效，哪些没做好）

**有效的手法**
- **小节 + 理解检查**：每讲完一节停下，amber 的误判（向量+BM25 能解混淆）当场暴露，及时纠正，避免带着错误前提进实操。
- **纠偏驱动设计**：amber 的真实业务直觉（财报严谨、字段独立）两次纠正设计——一次改哲学（unknown 不兜底），一次爆真 bug（L3 跨指标误吸收）。说明"让学员用真实领域知识挑刺"比"老师单向灌输"更靠谱。
- **踩坑必须终端输出**：三个 SSE 坑每个都先抓 `laravel.log` / curl 原始响应再下结论，没有"我觉得是 X"的猜测。

**没做好的 / 下次的改进**
- **演示诱惑**：为了展示 L0 unknown 机制，一度把"净利润"强行划 unknown。这是"为教学牺牲严谨"的反面教材——被 amber 一句话点醒。以后演示机制要用 legit 的未知字段，不拿可识别字段凑。
- **Edit 静默未落盘**：Python 侧 `auto_approve` 参数 Edit 后磁盘没变，导致 500。改完关键文件应 grep / 读盘核验，不能信工具返回值（这也是收尾 skill 的硬规矩）。
- **Laravel 坑可前置预防**：三坑（协变 / 不可遍历 / ob_flush）都是 PHP SSE 转发的经典坑，如果实操前先给一段"Laravel SSE 转发三忌"的提示，能省一轮调试。下次 W10/W11 涉及 Laravel 时前置。
