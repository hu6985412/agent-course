## 二、对话实录

> 以下按主题还原。为可读性做了压缩，但**技术讨论、错误和判断都是原始的**。

### 主题 1 · 阶段1 五小节引导（对方抓住了核心）

- **第1节 查询修饰**：我列了三类手法（多查询扩展 / HyDE / 指代消解），给 2026 主流结论（解析用 Docling、改写用 HyDE+Multi-Query）。对方抓到"财报数据固定精准、用户提问不精准——所以查询侧优化的增益在财报场景有限，文档侧（解析质量）可能更关键"。
- **第2节 父子分段 small-to-big**：讲只 embed 子块、返回父块；表格当原子块不劈。对方用 SQL 类比答"子块像二级索引条目、父块像主表行；表格一行是不可再分元组"，并判断"跨页表格断裂 + 脚注污染是脏数据主因，重排救不回"。
- **第3节 PDF 解析路由**：讲 Docling（主）+ pdfplumber/PyMuPDF（回退）+ OCR/VLM（Tier3 扫描件）。对方拍板"能用一套本地免费方案（Docling）就别上 OCR 成本"，复杂表格升级 Tier2、扫描件才升级 Tier3。
- **第4节 上下文压缩**：讲用 LLM 把长父块压成关键句再喂生成。对方认同"先扩展查询 + 压缩候选，缓解重排太慢的痛点"。
- **第5节 GraphRAG**：讲实体/关系图谱。对方判断"图谱构建成本高、收益在跨文档多跳才显著，单文档用不上，了解即可"。

### 主题 2 · PDF 解析链路 + 父子分段实操（真实坑）

- **解析回退链**：Docling 主、pdfplumber 回退、PyMuPDF 兜底。回退分支踩了 `enumerate(pdf)` 应改 `enumerate(pdf.pages)` 的 bug（PDF 对象不可迭代），修后沙箱也能验证。
- **入库统计**：华夏银行 2026 半年报解析后得 **458 父块 / 623 子块，其中 228 个表格原子块**——表格完整不劈，LLM 拿到的总是整表。
- **父子分段验证**：`test_split.py` 用构造的示例 markdown 验证"表格原子（子块数==1，内容完整）"与"长文本滑窗切多个子块"，golden rule 成立。

### 主题 3 · HyDE 评测 + 饱和效应诚实修正（本周最值钱的部分）

- **饱和效应**：15 题四策略 A/B，`Recall@10` 全 1.000（小语料 top10 必含全部块），baseline 和多查询打平。我一度怀疑"多查询增益不如 HyDE"是错觉。
- **诚实修正**：分维度看 `MRR@10` 才显形——baseline 0.933 / **HyDE 1.000** / 多查询 0.900。HyDE 把正确答案顶到第一；多查询反而因"扩写引入伪相关块"让首位命中率略降。修正了"多查询增益一定 > HyDE"的直觉。

### 主题 4 · 执行规范固化（跨课程）

对方明确：阶段2 实操**全部基于 PowerShell**，前置调用 `start-env-windows.bat` 加载 API 参数，其他配置（PG_ 连接）手写 `$env:XXX=`，依赖手写 `pip install`，**不再给 .sh 命令**。已写入长期记忆「实操执行规范」段，W08–W16 复用。

## 四、方法论总结（这一周沉淀下来的）

1. **预期要可证伪，别拍胸脯**：我一度怀疑"多查询增益不如 HyDE 是错觉"，实测分维度看 MRR 才翻案——HyDE 顶第一、多查询反而稀释首位。正确姿势是"预期 X，跑出来验证"，被真实数据修正的结论比漂亮预测值钱。
2. **小语料会伪造指标**：15 题 / 458 块，top10 必含全部块 → Recall 全 1.000 是天花板。真实区分力在 MRR 与"故意加口语/异名词难题"。评测集规模不够时，别把 Recall 当真值。
3. **检索层救不了入库脏数据**：跨页表断裂、脚注污染一旦进库，重排也修不好——第一杠杆是"更干净的入库"（父子分段 + 表格原子不劈）。
4. **踩坑必须有终端输出作证**：pdfplumber `enumerate(pdf.pages)` 这种真实报错驱动的定位，不是脑补——每个坑都要有终端输出或真实数字兜底。
5. **执行规范跨课程固化**：PS + bat 加载 + 其他配置手写 + 不提供 .sh；依赖统一走 managed venv。W08–W16 复用，不再踩这些环境坑。
