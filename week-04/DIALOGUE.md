- 一次只讲一小节，讲完必须停下来等对方的终端输出

## 二、对话实录

> 以下按主题还原。为可读性做了压缩，但**所有输出、错误和判断都是原始的**。
> 我的失误也没有修饰——它们在这份文件里的价值跟正确答案一样高。

### 第 1 节 · ReAct：把 W03 的循环正式命名

**我讲**：W03 那个 while 循环的本质就是 Action → Observation → Action，已经是 ReAct 了，只是没说破。ReAct 三段 Thought/Action/Observation 对应 W03 循环里的 assistant content / tool_calls / tool 消息。强调：ReAct 不是新框架，是一种"提示 + 循环"的范式。类比：像 Controller 里多步业务编排（先想查订单状态，调 Service，拿结果，再想物流拦截）。

**对方的反馈（抓到本质，精度我补了一句）**：

> "react 循环 模型自己判断安排下一步做什么，拿到结果后再干什么，而 controller内则是固定流程，只能根据预设的参数判断该执行什么；"

**我的修正**：他说"模型自己判断下一步"对，但要补精度——**工具集合（能调哪些 Service）是固定的，像 Service 目录里那排类；但『下一步调哪个、传什么参、调完怎么走』是模型运行时根据 Observation 现编的**。所以区别是"开发者预设流程 vs 模型运行时编排"。

---

### 第 2 节 · 记忆三层：循环跑久了会失忆

**我讲**：W03 循环每转一圈 messages 变长，导致①撑爆窗口②每轮更贵③噪声淹没信号。解法=记忆三层：①历史（全留，未必每轮发）②摘要压缩（过程与推理压成叙事）③外部存储（事实数据用时再取）。重点区分：摘要压"过程推理"（压了不出事），外部存储存"事实数据"（压了会失真变脏数据）。

**对方的反馈（精准，直接点出分水岭）**：

> "外部存储，这部分数据属于查询出来的详情数据，不应该放进会话，只需要在需要用的时候，使用即可，也不适合当摘要压缩，会失真，会变为脏数据。"

**我的确认**：完全正确，"失真/脏数据"用得准。补一句钉死边界：②摘要压的是"过程与推理"，③外部存储存的是"事实数据"，压了可能改值就是失真。那 3k token 订单详情走外部存储，对话只留"已查 NO2026… 状态=shipped"。

---

### 第 3 节 · 防护四件套

**我讲**：在 W03 的 `MAX_STEPS` 基础上补全四件：①步骤上限（兜底墙）②超时（Guzzle timeout 类比）③token 预算（接口限流类比）④重复调用检测（Stripe Idempotency-Key / Laravel 队列 unique 类比）。④是专门针对死循环的精准拦截，标准验收要故意造一次死循环。

**对方的反馈（点出误杀核心）**：

> "工具名+参数 一样才算重复， 如果单工具名，不同参数的查询就都会被误杀"

**我的补充**：对，只按工具名判重会杀掉"查订单A→查订单B→查订单C"这种正常推进。但纯"工具名+参数"漏杀"换参数打转"（A失败B失败C失败），所以生产叠二级熔断（同工具连续失败N次也拦）。本周造的死循环是"同一失败调用反复重放"，标准定义直接命中。

---

### 第 4 节 · 审计落库 + 实操全景

**我讲**：建两张表 runs(主表)+steps(明细) 1:N 落地，把 ReAct 三段和防护状态全存下来，既能回放又能做外部存储。给出 W04 实操六步全景（升级循环/摘要压缩/四件套/落库/退款业务场景/死循环验证）。然后问两件事：①业务场景用订单→物流→退款 OK 吗，还是换财报；②本地有 MySQL 吗还是先用 SQLite。

**关键转折——对方抛出预置的本地库**：

> "本地数据库 已经配置了一套预置的 `agent_runtime_schema.sql`（一份本地 SQL 建库脚本），本地数据库连接用这套配置：DB_HOST=127.0.0.1 / DB_PORT=3306 / DB_USERNAME=root / DB_PASSWORD=空。修改下课程，用这套数据库配置是否能达到效果，或者看那些有缺失字段需要补充？"

**我做的事**：用 pymysql 直连验证（root 空密码本地登录正常，11 表齐全），核对覆盖度为 W04 需求超集，指出缺口：`messages` 缺 `kind`+`metadata`（摘要压缩标记）、`runs.agent_id` NOT NULL 需先 seed agents。然后让他拍板。

**对方决策（AskUserQuestion）**：选「必须项+可选增强全补」+ 场景保持「订单→物流→退款」。

**我执行**：ALTER 补 `messages.kind/metadata`、`steps.guardrail/dedup_key`、`runs.ended_reason`；seed agents 一行（slug=refund-agent）。然后写 `w04-scratch/agent.py`，mock 三场景跑通，修复两个内部 bug（conversation_id NOT NULL、摘要压缩重查需独立 done_tools 状态），让他本机跑真实模式。

### 排错现场一：真实模式报 HTTP 400（压缩悬空）

**他贴了完整 Traceback**：真实模式第 4 轮 `urllib.error.HTTPError: HTTP 400: Messages with role 'tool' must be a response to a preceding message with 'tool_calls'`。

**我定位根因**：旧 `maybe_compress` 按 tool 索引切分，第 3 轮末把 `assistant(tool_calls)` 删了却留下它的 tool 响应，制造悬空 tool 响应。前 3 轮没报错是因为压缩在第 3 轮末才首次触发。

**我做的修复**：① `maybe_compress` 改成按"完整工具交互块"（assistant+其全部tool响应）为不可分割单元，整块保留或整块压缩；② `KEEP_RECENT` 3→2 让正常流程也能演示压缩；③ 新增 `validate_messages` 防御校验 + 发请求前拦截（带 `_dump_messages` 诊断）；④ 修 `validate_messages` 自身误报（一个 assistant 多个 tool 响应连续排列是合法的）。

**验证**：写临时单元测试覆盖"他报错同款 3 块场景 + 4 块场景 + 不压缩场景 + 旧逻辑复刻"，新逻辑 validate 零问题，旧逻辑确认悬空；mock 整体重跑正常。测试文件删了。

---

### 排错现场二：死循环④ 真实模式没触发——但发现了更好的事

**他重跑三个场景（贴真实输出）**：run9 正常退款 done（tokens≈363）、run10 不可退款 done（tokens≈318）、run11 物流故障 done（tokens≈407）。

**我查库发现的真相**：run11 物流接口两次 500，但模型**只重试 1 次**就跳去 `decide_refund`，④ 没机会拦。而④ 的实证其实在更早的 mock run5（`--deadloop`，`status=guarded/repeat`）。

**我的判断（诚实披露）**：这不是 bug，是真实 LLM 的**优雅降级**——遇到工具故障自己绕开。所以验收"死循环被拦"由 mock 实证支撑，真实模式暴露了更好的工程现实。我把这个写进正文坑 2，没假装真实模式拦下了。

**他确认**："正常了"。

## 四、这套对话里的方法论（给想复用的你）

| 做法 | 为什么有效 |
|---|---|
| **逐节讲 + 停下等反馈** | 四节内容量大，一次倾倒会跟不上；停下来确认每一节真懂，再进下一节 |
| **让他动手判断数据归属** | 他凭直觉说出"外部存储不会失真变脏数据"，印证"类比 + 让他动手"比讲概念有效十倍 |
| **用 PHP 类比一切新概念** | Controller 编排、audit_log、物化视图、Stripe 幂等键——每个抽象都挂回他已有的知识树 |
| **真实输出驱动讲解** | 他贴回真实 API 输出后，我照着讲"模型自愈"，比预演扎实（也纠正了我"模型会死循环"的预设） |
| **预测-验证（W01 传承）** | 压缩 400 排错用了"前 3 轮没报错 = 压缩在第 3 轮末才触发"的对照推理，同样有效 |
| **错了立刻改口** | 他质疑 ReAct 定义后我立刻补精度；④ 没触发我没硬说"拦下了"，而是如实记录模型自愈 |

## 五、这次没做好的地方

如实记录，供下一周改进：

1. **压缩 bug 在真实模式才暴露**。mock 模式因为 KEEP_RECENT=3 没触发压缩，所以 400 一直没在测试期冒出来——直到 amber 真实跑（轮数更多）才炸。下次：mock 也要覆盖"会触发压缩的轮数"，别让 mock 和真实差太远。
2. **validate_messages 自己写错了一版**（误判"tool 紧邻前一条必须是 assistant"）。这版被自己写的临时单元测试逮到，没流出去。但说明复杂协议校验还是得靠"构造反例"验证，不能拍脑袋写。
3. **死循环④ 真实模式没触发**，预期管理要提前说清：mock 验证逻辑、真实验证自愈，两者都算验收，别让学习者以为"真实模式必须拦下才算过"。
4. **Layer 2 摘要压缩在真实模式会再打一次 LLM**，消耗 token——本期如实标注了，但下次可以把"摘要用更便宜模型"作为默认建议写进代码注释。
