## 二、对话实录

> 以下按时间顺序还原。为可读性做了压缩，但**所有输出、错误和判断都是原始的**。
> 我的失误也没有修饰——它们在这份文件里的价值跟正确答案一样高。

### 第 1 节 · tool_call → 执行 → 回填 → 再请求，到底发生了什么

**我讲**：LLM 不会真的"调用"任何函数，它只产生"调用意图"（tool_calls）。你的 while 循环才是执行引擎。类比：把 LLM 想成"只会出 SQL 执行计划的 DBA，不会自己跑查询"——`User::find($id)` 在你脑子里是"立刻拿到对象"，在 Agent 里模型只返回 `tool_call: get_user(id=123)`，数据它没碰过。

**我画了一次完整的六步消息流**：① 发 messages（1 条）→ ② 模型返回只有 tool_calls → ③ 代码执行 get_weather → ④ append assistant 消息 + tool 结果 → ⑤ messages 变 4 条 → ⑥ 模型第 2 轮给最终回答。

**关键细节我点了三个**：`messages.append(msg)`（带 tool_calls 的 assistant 消息必须先留着）、`tool_call_id` 必须回传、while 必须有出口。

**对方的反馈**：

> "1. 只负责规划，不负责实际执行；2. 都能理解；3. 规划和执行结果通过 tool_call_id，进行关联，告诉模型规划内容和执行结果"

**我的修正（精度很重要）**：第 3 点理解对了一半。模型**本来就知道自己规划过什么**（那条 assistant 消息一直留在 messages 里）。`tool_call_id` 真正的意义是**锚点**——模型发出 `call_1`，你的 tool 消息必须带同一个 `call_1` 回来，模型才能把"结果"精确贴回"当初那个意图"。丢了 id 或对不上，模型收到一个不认得的 tool 结果直接报错。**规则：assistant 消息原样留着 + tool 消息回传同 id，缺一不可。**

---

### 第 2 节 · 工具的粒度、命名、描述

**我讲**：工具 `description` 是模型能读到的唯一 API 文档。类比 composer require 一个包，你读 README/PHPDoc，不读源码；模型连源码都没有，description 就是它的 PHPDoc。引用 2026 年工程复盘：清晰描述 vs 模糊 → **+16%** 调用准确率，加 examples +7%，加约束 +3%（明确标注：这是外部复盘，非本课实测）。

**命名**：动词+名词，像 Laravel 命名路由（`query_order` 不是 `process`）。**粒度**：一个能力一个工具，变化走参数（查订单按单号/按用户都是同一个 `query_order`，靠参数区分，不拆两个工具）。

**我让对方动手**：让他凭直觉给"查 MySQL 订单"写一句 description。

**他的原话（已接近生产级）**：

> "查 mysql 最好按模块划分，例如查询订单信息工具的描述：用于查询商城订单数据，根据用户提供的订单编号或用户 id 进行查询，当需要获取对应订单数据时使用；"

**我的处理**：三要素（做什么+怎么查+何时用）齐全，属甜点区。只微调加了个具象场景"发货状态"，并点出"按模块划分"正是粒度甜点区的实操落地——一个实体一个工具，变化走参数。

---

### 第 3 节 · 失败返回错误字符串，绝不抛异常

**我讲**：工具内部异常必须 catch 转字符串回填，绝不冒泡。类比 Laravel：Controller `throw` 未捕获 → 请求 500 挂掉；返回 422 + 错误信息 → 前端能修正重试。模型扮演"会读错误信息自我修正的 API 客户端"。

**我点出"查 MySQL"是头号异常源**：DB 连接超时、SQL 报错、字段不存在、单号查不到。还埋了一个伏笔：错误回填解决单次失败不死，但反复调同一失败参数会烧 token——所以 while 要加步数上限（W04 防护伏笔）。

**我顺带种了安全钩子**（W15 铺路）：让模型传 raw SQL 执行 = 拼接用户输入进 SQL，注入漏洞。正确做法是工具只接收结构化参数，SQL 写死、参数走预处理。

**对方的反馈**：

> "1. 能理解；2. 查 mysql；"

即认同 422 类比，并凭经验指出"查 MySQL"最可能抛异常。直觉准确——我们的 `query_order` 的 try-catch 包裹层对它最重要。

---

### 第 4 节 · 并行调用与幂等性

**我讲**：独立只读可并发（类比 Guzzle concurrent()，延迟从求和变取最大）；并行的陷阱是"没有 per-call timeout 就全回合卡死"，要用 allSettled 而非 all。

**重点是幂等性**：写操作（发通知）重试是地雷——服务端可能已发出，只是网络超时你没收到回包，一重试又发一条。类比 Stripe `Idempotency-Key` / Laravel 队列 `unique` 去重键。**幂等键必须从"操作内容"派生，不是随机 UUID**——否则两次重试算出两个 key，照样双发。

**我给了决策矩阵**：含写操作或有依赖 → 串行；独立只读 → 并行。我们的 `send_notification` 是唯一写操作，必须带幂等键+串行；`get_weather`/`query_order` 只读可并行。

**对方的反馈**：

> "1. 理解；2. 认同；"

### 排错现场一：PowerShell 的 `export` 报错

**他贴了报错**：

> `export : The term 'export' is not recognized as the name of a cmdlet...`

**我讲**：这是 PowerShell 和 Git Bash 语法差异。`export` 是 bash 命令，PowerShell 用 `$env:变量 = "值"`。且 bat 用 `powershell -NoExit` 启新子进程，变量只在弹出窗口有效。解法：双击 bat 注入变量，在弹出窗口跑；或手动 `$env:API_KEY = "..."`。

---

### 排错现场二：变量名对不上 + Edit 静默失败（老坑复发）

**他提**：`start-env-windows.bat` 已配了三个参数，能否统一利用避免重复设。

**我查**：bat 设的是 `API_KEY/BASE_URL/MODEL`（无前缀），agent.py 原读 `OPENAI_API_KEY`（带前缀）——名字对不上，导致 bat 配好的读不到。改对齐。

**踩坑**：Edit 工具报 Success，但 `real_llm`/`main` 两处旧代码**根本没写入**（本系列第三次踩：W01/W02 各一次）。改用 `replace()+assert` 强制改并独立读盘校验才确认生效。

**验证**：用无前缀变量跑 `agent.py`，不再自动切 mock，证明 `API_KEY` 被读取。

---

### 排错现场三：真实 API 返回 403 Forbidden

**他贴了完整 Traceback**：`urllib.error.HTTPError: HTTP Error 403: Forbidden`。

**我加诊断**：在 `real_llm` 加标准 `User-Agent` 头（很多中转站对 urllib 默认 UA `Python-urllib/3.x` 直接 403），并捕获 `HTTPError` 打印打码 key + 完整 URL + 响应体，便于定位。

**关键线索他给了**：「之前直接 `curl.exe` 是正常能连接 AI 的」。

**我定位根因**：curl 默认 UA 是 `curl/8.x` 放行，urllib 默认 UA 被 WAF 当异常脚本客户端拦截——和业务逻辑无关，是传输层把客户端识别成不受欢迎来源（类比 Nginx 网关规则拦了合法请求）。加 UA 头后重跑即通过。

---

### 真实模式跑通

**他贴了真实输出**：模型自己选了 `get_weather` / `query_order` / `send_notification`，造了参数（city=北京 / order_id=NO20260911001 / to=U1001+message=您的订单已发货），第 2 轮给最终回答，还基于工具返回做了推理（"订单状态已发货，通知内容吻合"）。**步②真实 tool_call 循环跑通。**

**我做了步②验收讲解**，指出 4 个学习点（模型自己选工具造参数 / messages 1→5 暴涨 / 3 个 tool_calls 一次性返回但串行执行 / 模型基于结果推理），然后问步③路线。

**他拍板**：「先收尾 W03，PHP 推迟到 W09」。合理——本周边把"零框架手搓循环"吃透，PHP 落地留到框架周。

## 四、这套对话里的方法论（给想复用的你）

| 做法 | 为什么有效 |
|---|---|
| **逐节讲 + 停下等反馈** | 四节内容量大，一次倾倒他会跟不上；停下来确认每一节真懂，再进下一节 |
| **让他动手写 description** | 他凭直觉写出接近生产级的描述，印证"类比 + 让他动手"比讲概念有效十倍 |
| **用 PHP 类比一切新概念** | DBA 出计划、PHPDoc、422、Stripe 幂等键——每个抽象都挂回他已有的知识树 |
| **真实输出驱动讲解** | 他贴回真实 API 输出后，我照着讲"模型自己选工具造参数 / messages 暴涨 / 基于结果推理"，比预演扎实 |
| **预测-验证（W01 传承）** | 这周没用上数值预测，但 403 排错用了"curl 能过 = Key/URL 对，差异只在请求长相"的对照法，同样有效 |
| **错了立刻改口** | 他质疑 description 后我立刻微调；Edit 静默失败时我换 replace+assert 并明说"工具不可信" |
